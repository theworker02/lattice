# Contributing to LATTICE

LATTICE welcomes contributions that make the project clearer, safer, more testable or more buildable. The project is early-stage and intentionally separates concepts, simulations and physical evidence.

## Good first contributions

- Clarify a document, glossary term or diagram so a non-specialist can follow it.
- Find an inconsistency between a claimed maturity level and its evidence.
- Improve a simulator test or document a model assumption.
- Propose a material, optical, mechanical or test approach with source data and stated limits.
- Improve the M1 pilot, DVP, RFQ or DFM risk register with a concrete question or measurable acceptance criterion.

## Before proposing hardware changes

State what is known, what is assumed, what physical test would distinguish alternatives, and which current document would change. Do not mark a hardware feature as validated from a rendering, a calculation or a simulation.

## Scope boundaries

Do not add secrets, vendor-private drawings, proprietary firmware, unlicensed assets, supplier pricing shared in confidence, or unsafe wiring instructions. Do not make public claims about certification, energy yield, IP rating, sensor accuracy or production readiness without actual evidence.

## A useful issue or pull request

Use a short title, name the affected folder/document, describe the problem, show the evidence or source, explain the proposed change and list any test/documentation update. For a material or manufacturing proposal, link it to the relevant M1 gate and DVP row.
