# LATTICE plain-language glossary

| Term | Plain-language meaning |
| --- | --- |
| Signal Cube | The proposed cube-shaped LATTICE product that senses conditions and routes useful messages locally. |
| Mirror scale | One overlapping reflective piece on the Cube’s exterior. Most are appearance pieces; selected positions can be functional cassettes. |
| Cassette | A small, replaceable surface assembly with one job, such as measuring light, collecting a small amount of solar energy, or sensing temperature. |
| Central core | The protected structure inside the Cube holding the controller, power circuits, wired connection and cassette interfaces. The dark middle band shows its perimeter. |
| S-L | Light-sensing cassette. It needs a known optical window or partly transmitting mirror stack. |
| S-P | Photovoltaic cassette. It measures/generates electrical energy from transmitted light; it is not the same thing as a light sensor. |
| S-T | Surface-temperature cassette. It can sit behind an opaque scale because it does not need to see light. |
| LSP | Lattice Signal Protocol: the proposed common language for a value such as a temperature, a Boolean state, or a structured record. |
| LatticeLink | The proposed physical wired connection concept for power, identification and data between compatible modules. |
| Passport | The digital description of a module: its identity, version, inputs, outputs, power needs and health information. |
| Twin | The software-side representation of the physical system, used to inspect topology, values, history and faults. |
| Observatory | The local LATTICE interface that shows the Twin, scope/history, routing and faults. |
| M1 Pilot | The proposed 12-unit engineering build intended to create real material, assembly and test evidence. |
| DVP | Design verification plan: a list of tests, test setups and evidence required before a design decision. |
| First article | The first complete build made from a proposed process, inspected before more units are assembled. |
| DFM | Design for manufacturing: changing or refining a design so it can be built repeatably and serviced. |
| NRE | Non-recurring engineering: one-time engineering, fixture or tooling work before units can be built. |
| Concept | An idea or plan that has not yet been physically proved. |
| Simulated | Software behavior tested in a model; not evidence that real hardware works. |
| Validated | A physical revision has passed defined tests with recorded evidence. No LATTICE hardware has this label yet. |

If a document uses a term that is not explained here, add it before expecting a newcomer to understand it.
